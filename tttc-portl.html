SOFTWARE LICENSE DISTRIBUTION

UX Design · SaaS Platform

Designed a system to streamline software license distribution across students, faculty, and administrators, replacing manual workflows with a scalable, structured solution.

Outcome: Reduced operational friction, improved visibility into license usage, and enabled confident self-service workflows for admin teams.

Think Tank Training Centre

Background

Software license distribution at Think Tank was handled manually by the IT team, creating inefficiencies across purchasing, tracking, and allocation.

The process involved multiple stakeholders, lacked visibility, and frequently resulted in delays, errors, and support overhead.

Project Goal

Design a centralized system to manage software license distribution across multiple user types.

Enable administrators to purchase, track, and allocate licenses efficiently, while ensuring students and faculty receive access with minimal friction.

A CLOSER LOOK

System Requirements

Students:

The system needed to support three primary user groups with distinct needs:

  • Students: Access required software quickly and reliably
  • Faculty: Ensure alignment with student tools before term start
  • Admin: Manage purchasing, allocation, tracking, and revocation of licenses
Admin:
  • Should to be able to see if they need to purchase more keys for a particular software for a particular term (outside of PORTL).
  • After purchasing, easily bulk add keys to the portal and prepare them for distribution.
  • Issue purchased keys to students and faculty (alumni can be included here).
  • View, edit, create new software with details and key format.
  • Remind a user if a payment is pending.
  • Revoke keys.
  • Receive confirmation of the software activation by the user.

Key Design Decisions

1. Centralized Admin Dashboard

Instead of fragmented workflows, I designed a single interface where admins could manage all license-related actions.

2. Visibility-Driven Structure

Prioritized clear visibility into available, used, and required licenses to support purchasing decisions.

3. Bulk Actions for Efficiency

Enabled bulk upload and distribution of licenses to reduce repetitive manual work.

Tradeoffs
  • Reduced flexibility in favor of clarity and speed
  • Deferred advanced automation features due to timeline constraints

Main Admin view (click the image to zoom in)

The admin interface was structured to reflect key system states and enable quick decision-making around license distribution and purchasing.

  • Software—has a list of software packages and allows to edit/delete each software (each has multiple parameters that help avoid duplication).
  • Type of access—reflects the way the software keys are distributed to the users, can be edited.
  • Total used—the number of already purchased and distributed keys. Admin can view a list of users that are currently using this software. For some software keys can be revoked, depending on the type of licence.
  • Total available keys—the number of purchased keys that are ready to be distributed. Admin can add more purchased keys, view list of users currently using the software, and are able to revoke the keys depending on the licence type.
  • Total keys required to purchase—is the number per each software, that the admin needs to buy directly from a distributor. Each item has a summary and multiple parameters
